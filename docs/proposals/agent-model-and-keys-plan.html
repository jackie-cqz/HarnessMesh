分两步做

步骤做什么怎么验（都不调真模型）
1. 会话里切模型 / 模式
  • daemon 读 session/new、session/load、set_config_option 返回的选项和 config_option_update 通知，存在会话上；用户的选择单独记一份，重启后 load 完再设一次。
  • 新接口 POST /local/sessions/{id}/config 和对端同名路由：只有会话打开者能改，只在两轮之间改，值由 agent 校验（opencode 对不存在的模型直接报错）。
  • agent 卡片缓存最近一次见到的选项列表，新会话页第一条消息前就能选。
  • 面板输入框下加下拉；CLI 加 hmesh session config；mesh_get_session 返回当前模型。
测试 agent 加上选项；端到端：选模型 → 重启 daemon → 恢复后仍是这个模型；对端打开者能改、别人不能；面板冒烟截图；真实 opencode 只切不发消息
2. 按 agent 配 key / 地址 / 默认模型
  • 存在 <数据目录>/agent-secrets/<agent_id>.json，权限 0600；接口只写不读，界面显示「已设置 · 末 4 位」。
  • 启动 agent 进程时按上表换成环境变量；不碰用户自己的 opencode / claude 配置文件。
  • 默认模型：现有的 adapter.model 字段从「仅记录」改成真生效（建会话后按 category=model 设置），所有 ACP agent 通用。
  • 注入的值加进脱敏名单，事件和日志里不会出现原文。
  • key 的接口只挂在本机 owner API；配对电脑的 agent 列表只多一个「已配置 / 未配置」。
本机起一个假的模型服务商，看它收到的请求头里是不是配置的 key；全量事件和日志里搜不到 key 原文；用对端身份调接口拿不到 key

要你定的事

  1. key 存哪：数据目录里权限 0600 的文件（推荐：和节点私钥同一级保护，Mac / Windows 一套代码）；或系统钥匙串（更安全，但每个系统写一套，可以以后加）。
  2. 配对电脑能不能改它打开的会话的模型：能（推荐，打开者本来就管自己的会话）；key 一律不能从对端改。
  3. agent 委派时能不能指定子会话的模型（mesh_send 加 model 参数）：先不做（推荐），子会话用对方 agent 的默认模型。
  4. 运行中能不能切：只在两轮之间（推荐）；运行中切的行为各家不一样。
  5. opencode 的 key 怎么给：环境变量注入自定义服务商（推荐，只影响 HarnessMesh 起的进程）；或像 codeg 那样改 ~/.local/share/opencode/auth.json（会连带改掉你在终端里用的 opencode）。
  6. 顺序：先做第 1 步（推荐：标准接口、改动小、opencode 已验证），第 2 步接着做。

没证实 / 风险

  • key 真的被带到请求里：注入后模型出现在列表里已证实，但请求头里的 key 要发一次消息才能看到。做法是本机起假服务商，第 2 步一开始就验。
  • Claude Code、Codex、Pi 没装：变量名来自适配器源码、README 和 codeg 的用法，装上后要各跑一次。
  • 选项 id 各家不同：按 category 识别，没有 category 的选项照样显示但不参与「默认模型」。
  • 选项会变：opencode 切到 haiku 后多出「思考强度」；每次以 agent 返回的完整列表为准重画。
