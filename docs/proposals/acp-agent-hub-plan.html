关键依据：ACP 规范规定，客户端建会话（session/new）时可以传一组 MCP 服务器，agent 必须支持 stdio 方式连接。所以 HarnessMesh 启动会话时就能把 hmesh mcp 交过去，不用你给每个 agent 手配。OpenCode 和 Claude 适配器的源码都确认会接收这组服务器。

两种用法怎么走

你在 A 的界面直接用 B 的 OpenCode（远程操作）

  1. A 的侧栏里有 mac-b / OpenCode，点开就能输入。
  2. A 的 daemon 经 mTLS 请 B 开会话。B 对 A 设的是 auto 就直接开；设的是 confirm 就先在 B 的界面批准一次。
  3. B 的 daemon 用 ACP 启动 opencode acp，建会话时交出 hmesh mcp。
  4. OpenCode 的输出、工具调用实时推回 A 的界面；B 的界面也看得到。
  5. OpenCode 要先问才能运行 bash 时，权限请求弹在 A：谁开的会话谁来批。
  6. 可以接着聊、取消；关掉 A 的界面再打开，会话还在。

A 的 Claude Code 叫 B 的 OpenCode（agent 互相调用）

  1. A 上 Claude Code 的会话已经带着 hmesh mcp。
  2. 它调用 mesh_send(agent="mac-b/opencode", message=…)。
  3. B 开会话（同左边第 2、3 步），界面上标明「由 mac-a / Claude Code 发起」。
  4. 权限请求按 B 对 A 的设置处理：auto 自动答「允许一次」并留记录；confirm 弹在 B 的界面。
  5. 第一轮结束后，最终回复交回 Claude Code：{session_id, final_text}；带上 session_id 再调就接着聊。
  6. 调用链受限：限制深度，同一条链不能回到链上已有的会话（上限见「还要你定的」）。

安全底线

谁能让我的 agent 干活

  • 配对就是信任边界。被叫起的 agent 按它所在电脑的本机配置行事：比如 Claude Code 自己设了允许 bash，就不会再来问。
  • 不放心的对端设成 confirm：它开的会话要先在本机批准，agent 叫起的会话里的权限请求也弹给你。
  • 撤销配对立即生效：进行中的远端会话取消，排队的拒绝。

交给 agent 的东西

  • 只交我们自己的 hmesh mcp（固定命令和参数，会话专属 token），不转发来自项目文件或 agent 输出的 MCP 配置，这也是 ACP 规范的安全要求。
  • 每次 mesh_send 都带上调用链，限制深度、禁止回环、限制同时派活数。
  • CI 只用会说 ACP 的假 agent；每次真机验证都先问你。

不做

不做编辑器插件；不帮你安装 agent；不替代各 agent 自己的登录和模型设置（在 agent 自己那里设）；不做云端中转，电脑之间仍然直连；不做 codeg 那些外围功能；CI 里不调用真实模型。
