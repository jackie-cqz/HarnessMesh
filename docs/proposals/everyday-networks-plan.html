日常网络场景补齐：电脑换了 IP 自己找回来，一台电脑在局域网、Tailscale 和云服务器中继上都能被连到，到了陌生网络不开端口

2026-11-26。核查结论：日常最常卡住的是「电脑换了 IP 就失联」。原因有三处：直连只监听一个固定 IP；每台电脑的名片里只有一个地址；名片只在 daemon 启动时推给对方，而且推不到只装 MCP 的电脑。其次是公司网络分网段、开客户端隔离，以及两台电脑都在 NAT 后面。方案分 5 个 PR：前 3 个补地址、监听和找回；第 4 个写「用云服务器连两台电脑」的文档，不改代码；第 5 个做内置中继。身份认证不变，还是 mTLS 加固定的证书指纹，再加配对。名片格式也不变，旧版本照常能用。

手动填的hmesh peers address <电脑> <地址:端口>，或者面板里电脑卡片上的「改地址」只存在本机
  • 拨号顺序：先试上次成功的那条，然后依次是同网段的 IP、主机名、Tailscale、中继。前一条 300 毫秒没响应，就同时开下一条，第一个对上证书指纹的胜出，记下来下次先用。
  • 主机名：用系统的解析，.local 由系统自己的 mDNS 解析。macOS 自带；Windows 10 以后自带；Linux 要装 nss-mdns，Ubuntu 桌面版默认有。解析出的每个 IP 照样要过现在的地址规则。解析错了最多连不上，因为对方必须出示配对时固定的那张证书。
  • 名片不动：名片里那一个地址仍然是主 IP，旧版本只看它。名片是严格校验的，多一个字段旧版本就整张拒收，所以多出来的地址放在新接口里。旧版本没有这条接口，新版本推过去失败就跳过，新旧之间按现在的方式工作。

PR 2：监听所有网卡，只对认过的网络开门

  • 怎么监听：监听 0.0.0.0 和 ::。每接进一条连接，在 TLS 握手之前先看两件事：它是从本机哪个地址进来的，那个地址所在的网络认没认过（Tailscale 网卡算认过）；来源在不在允许的网段里。有一条不满足，就直接断开。进门之后和现在一样：没配对的只能碰到配对接口，而且只在配对窗口里回应。
  • 怎么认网络（待你定，见下面）：推荐用「网段加上网关的硬件地址」。家里和咖啡馆可能都是 192.168.1.0/24，但网关不是同一台设备。
  • 到了没认过的网络：不接受连入，不广播，只往外连。面板顶部提示「这个网络还没认过」，点「信任这个网络」才开门。hmesh setup 时所在的网络自动算认过。
  • 地址变化：每 5 秒看一次网卡，地址变了就更新地址列表。推送改成「每变一次推一次」，不再是一次启动只推一次。
  • 配置兼容：现在的 network = "tailscale" 自动换成「只开 Tailscale」；network = "direct" 连同原来的监听地址，换成「认过这个地址所在的网络」。重跑 setup 不会丢掉已有的身份和配对。

PR 3：已配对的电脑互相找回，连不上时说清楚

  • 找回密钥：每台电脑有一把随机的「找回密钥」，配对之后通过要证书的连接交给对方；撤销配对时换一把，被撤销的电脑就再也认不出它。
  • 广播什么：只在认过的网络上，一直广播一个新的服务类型 _hmesh-find._tcp。名字是「找回密钥对当前 10 分钟算出的 HMAC」的前 16 位十六进制，不带电脑名，也不带指纹。现在「附近的电脑」用的 _hmesh._tcp 不变，配对窗口之外照样看不到它。
  • 怎么找：连不上某台已配对的电脑时，算出它这 10 分钟和上 10 分钟的标记，在局域网里听 1.5 秒，听到就连过去核对证书指纹。外人看到的只是一串每 10 分钟换一次的随机字符。
  • 按地址配对：配对弹窗里加一行「按地址配对」，填 IP 或主机名，再填对方屏幕上的口令。命令行的 hmesh pair join <地址> 已经有了。
  • 连不上时分层说清楚：依次是主机名解析不出来；连不到端口（多半是防火墙或网络隔离）；那个地址上是另一台电脑（指纹不对）；对方已经撤销了配对。电脑卡片上显示「上次连上：5 分钟前，经 Tailscale」。

内置中继怎么工作

问题做法
怎么装ECS 上运行 hmesh relay serve --listen 0.0.0.0:7443，打印一行中继码：地址、中继自己的证书指纹和访问令牌。安全组放行这个 TCP 端口。
电脑怎么用运行 hmesh relay use <中继码>，或者在面板「设置」里粘贴。之后这台电脑一直往外连着中继，地址列表里多一条中继地址，自动推给已配对的电脑。
谁能用这台中继只有拿着令牌的电脑。登记时要用自己的节点私钥签名，所以拿着令牌也冒用不了别的电脑的身份。中继码泄露了就换令牌。
防滥用按令牌限流，限制并发连接数，空闲连接定时断开；只转发登记过的电脑之间的连接，不能拿来上网。
国内 ECS用 IP 加非 80、443 的端口运行，不用域名，就不涉及网站备案。
陌生网络没认过的网络上不开端口，只连中继，别人照样能经中继用它的 Agent。
配对已配对的电脑会自动拿到中继地址。第一次配对仍然用配对码；配对码里可以写中继地址，这一点在这个 PR 里细化。

还要你定的事

1. 怎么认出「同一个网络」：网段加网关的硬件地址（推荐）好处：家里和咖啡馆即使网段一样，网关也不是同一台设备，不会认错；三个平台都能读到（macOS、Linux 读路由和 ARP 表，Windows 读邻居表）。代价：换了路由器要重新点一次「信任这个网络」；读不到网关硬件地址时（比如某些 VPN）退成只看网段，并且提示。另外两个做法：只看网段，最简单，但同网段的陌生网络会被当成认过；看 Wi-Fi 名称，直观，但 macOS 读 Wi-Fi 名称要定位权限，名字也谁都能起一样的，不推荐。
2. 做的顺序：1 → 2 → 3，文档随时插进来，中继最后（推荐）好处：每个 PR 都能单独验证、单独合并，前一个是后一个的地基；文档半天就能写完，先发出去，有 ECS 的人马上能用。代价：内置中继要等前两个合完，大约一周半以后。另一个做法是 1、2、3 合成一个大 PR：总时间差不多，但评审和回滚都更难。

风险和应对

监听所有网卡，暴露面变大应对：进门前双重检查，连接是从哪个本机地址进来的、那个网络认没认过，以及来源在不在允许的网段里，有一条不满足就在 TLS 之前断开；进门以后和现在一样。之前的方案和安全说明写过「不能监听 0.0.0.0」，这次要连同理由一起改掉。
认网络认错网段和网关硬件地址都相同的陌生网络很少见。网关硬件地址读不到时只看网段，面板会标出来。被认成可信的网络里，不认识的电脑照样只能碰到配对接口。
主机名解析到别的电脑应对：对方必须出示配对时固定的证书，解析错了只是连不上。解析慢的网络靠并行拨号和超时兜底。
广播让人知道「这里有台电脑在跑 HarnessMesh」你已经接受了这一点。标记每 10 分钟换一次，不带名字和指纹；只在认过的网络上广播；撤销配对时换找回密钥。
新旧版本混用名片格式和协议版本号都不改（名片校验要求版本号完全相同，改了旧版本会全部拒收）。新增的接口旧版本没有，新版本遇到就跳过。两台都升级以后，才有多地址和找回。
中继是公网上的新组件应对：令牌、节点签名、限流、并发上限、空闲断开，内容端到端加密；单独做一次安全评审，测试里检查中继转发的字节中找不到任何会话内容。只在本机模拟过，真实公网、ECS 安全组和运营商 NAT 的表现都没验证。
macOS 和 Windows 的系统权限macOS 上，往局域网地址连接和收发多播都要「本地网络」权限，PR #19 已经嵌入了 Info.plist。Windows 防火墙对监听所有网卡会问「专用 / 公用」；公用网络默认挡住入站，这正好和「陌生网络不开端口」一致，setup 会提示。

怎么验证

  • PR 1：两节点测试。B 换端口或地址后，A 通过地址列表找到它；主机名用 localhost 测解析；指纹不对的地址被跳过、换下一条；手动改地址；新节点对旧版本推地址列表失败，不影响原有功能。
  • PR 2：在测试里把 127.0.0.1 和 ::1 当作两个网络：只认其中一个时，从另一个进来的连接在 TLS 之前被断；地址变化后几秒内地址列表更新、推给对方；旧配置自动迁移；同时开 Tailscale 和局域网。
  • PR 3：轮换标记的广播和查找在 macOS 回环上测（Linux 和 Windows 跳过，和现在「附近的电脑」一样）；撤销配对之后，对方认不出新的标记；面板的「按地址配对」和分层提示走一遍冒烟测试，深色、浅色和窄窗口都截图。
  • PR 4：文档里写明没实测。
  • PR 5：本机模拟。B 不开任何入站端口，只连中继；A 经中继开会话、拿回答复；令牌不对、签名不对一律被拒；中继转发的字节里找不到会话内容；中继重启后两边自动重连。
  • 真机（要你配合，可以以后补）：笔记本换 Wi-Fi 后台式机自己找回；公司网络分网段；用一台 ECS 跑内置中继。

这次不做

  • NAT 打洞：中继已经能连通，打洞复杂、成功率看运营商，以后看需要再说。
  • 路由器端口映射（UPnP）和直接监听公网 IP：暴露面最大，有中继就不需要。
  • 网线或雷雳线直连（169.254 自分配地址）：太少见，这类地址也常被系统用作别的用途。
  • 多台中继互为备份：一台够用，地址列表以后可以放多条中继。
  • 在中继上做「附近的电脑」：经过中继的第一次配对仍然用配对码。
