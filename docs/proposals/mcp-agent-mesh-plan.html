一个前提先对齐：接上 MCP 的 agent 是发活方。MCP 只能由 agent 主动调用，没法把活推给它。真正干活的一方，是 daemon 用无界面方式拉起的 harness。所以“登记的 agent”指的是某台电脑上的一份配置：harness 类型、工作目录、模型，可以被反复唤起、按会话续聊。另一台电脑上你正开着的交互窗口收不到派来的活。

改完以后长这样

两台电脑是对称的，B 也能反过来给 A 派活。绿色是这次要新做或重做的部分。

派一次活：改前 → 改后

现在

  1. 发起方必须是 mesh 自己拉起的 Pi 1.4.0 任务，你自己的 agent 接不上
  2. 手写 scope JSON，把对方节点和 agent 的 UUID 写死
  3. 先在 A 上批准自己的父任务
  4. B 的主人要在 B 的终端敲 task approve <UUID>，面板只能复制这条命令
  5. B 起一次性进程：--no-session、清空环境变量，用不上本机已登录的配置
  6. 没有最终回复，只有一段段文本事件，要自己拼
  7. 想追问一句：不支持，只能重新派一个新任务

改完

  1. 任意 agent 调 mesh_list_agents，按名字看到所有电脑的 agent
  2. mesh_send("Windows-PC/pi-backend", "…")
  3. B 按节点开关直接执行；设成“需确认”的节点，在面板里点一下就行
  4. mesh_wait 拿到最终回复；要追问就带上会话 ID 再 mesh_send，接着上文继续

上手也从 14～19 步缩到 4 步：两台装好启动 → 配对一次（对方点同意）→ 面板里登记 agent → 给 agent 加一行 MCP 配置。

#目标能力现状改法改动量
①任意 agent 都能接 MCP只认 mesh 拉起、正在运行的 Pi 父任务，还要 scope 文件去掉父任务绑定，变成 hmesh mcp --data-dir …。后端本来就是用本机 owner 证书调 daemon，基本不用改小

要你定的事

1已配对的电脑派来的活，默认直接执行还是默认需确认？

推荐：默认直接执行，每个节点可以单独切到“需确认”。需确认时在面板里点一下就行，不用再去对方终端敲命令。

2干活的 harness 用本机原生配置，还是隔离配置？

推荐：原生配置为默认，能直接用已登录的 Codex、Claude Code，以及它们的技能和上下文；隔离模式保留为可选。代价是远端派来的活和你本机 agent 权限一样，只靠“限定工作目录 + 节点开关”兜底。

3外围功能怎么处理？

推荐：打一个 tag 留档，然后从 main 删除，不要只在界面上隐藏。留在 main 上会继续拖慢每次改动和测试。

4面板在现有代码上改，还是重写主界面？

推荐：重写主界面，后端接口复用。现有前端是压成长行的原生 JS，概念有 30 个左右，改比重写更费劲。

安全底线

  • 配对仍然是唯一的信任边界：没配对的电脑什么都看不到、什么都派不了。
  • 每个节点一个“自动执行 / 需确认”开关，随时可以撤销配对。
  • 每个登记的 agent 只在它登记的工作目录里干活。
  • MCP 返回的远端文本一律当数据处理，不能拿来扩大权限。
