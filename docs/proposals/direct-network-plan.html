加一种「直连」网络和局域网发现：局域网、ZeroTier、WireGuard 都能用，附近的电脑自动列出来，输对方屏幕上的 6 位口令就配好

2026-11-25。核查结论：现在只认 Tailscale，限制只在网络这一层的 5 处代码；身份认证靠 mTLS 加固定的证书指纹，再加上配对，这些和 Tailscale 无关。Tailscale 实际只帮了两件事：电脑之间连得上，以及 tailnet 外的设备根本碰不到端口。直连模式要把第二件补回来，靠的是「来源网段」加「配对窗口」。局域网发现只在配对窗口里广播，发现到的电脑用一次性 6 位口令确认身份，所以同一网络里的人冒充不了。连接建立以后的认证方式（mTLS 加证书指纹）不变。

问题做法
谁会出现在列表里直连模式、完整安装、并且正开着配对窗口的电脑。只装 MCP 的电脑只看、不广播（它不接受连入）。Tailscale 模式这次不参与。
广播什么服务名 _hmesh._tcp.local，带电脑名、地址、端口和协议版本；不带证书指纹
什么时候广播只在配对窗口里，窗口一关就撤回。平时局域网里看不到这台电脑
为什么要口令同一网段里任何设备都能广播一个也叫 studio 的服务，发现结果本身证明不了身份。要确认「选中的就是那台电脑」，必须用一样只出现在那台电脑屏幕上的东西。
为什么 6 位够口令走 SPAKE2：冒充的人每猜一次，都得真的跟你握一次手；错 3 次口令就作废（配对窗口照开，粘贴配对码不受影响），猜中的概率是百万分之三。简单地把口令做成哈希发过去不行：冒充的一方拿到哈希，一秒内就能离线试完 100 万种口令。
看不到对方时访客 Wi-Fi、公司网络、开了「AP 隔离」的路由器常常屏蔽多播。这时列表是空的，弹窗会说明可能的原因，照旧可以粘贴配对码。

粘贴配对码的老办法在所有模式下照旧可用，流程也不变。窄屏上流程图可以左右滑动。

这次不做

  • 监听 0.0.0.0、同时用几个地址（比如 Tailscale 加局域网）：名片里只有一个地址，先保持简单。
  • 域名和动态 DNS：现在完全不解析 DNS，加进来要另外设计。
  • 公网服务器经路由器端口映射（对外地址和本机地址不同）：暴露面最大。云服务器下一步走 SSH 通道，更安全。
  • 把 Tailnet 里的电脑也列进「附近的电脑」：可以用现有的 hmesh peers candidates 加探测实现，这次只做局域网。
  • 把粘贴配对码那条路也换成口令配对：等口令配对在局域网里用稳了，再考虑统一。

需要你定的事

1. 证书只核对指纹，不再核对 IP（推荐）好处：局域网 IP 变了、换网卡、换 VPN，都不用重新配对；只装 MCP 也不用提前写 Tailnet IP。安全上不吃亏：指纹已经锁死了唯一一张证书，握手又证明对方持有私钥，再核对 IP 不增加保护。代价：要改安全说明里的一句承诺。另一个做法是证书里写一个固定名字（节点 ID）、按名字核对，效果一样，但要处理已有证书里没有这个名字的情况，更复杂。
2. 配对窗口只在直连模式开启（推荐）直连的网络里谁都可能碰到端口，所以要关紧，局域网广播和 6 位口令也只在窗口里有效；Tailscale 模式照旧随时可以配对，现有的用法不变。另一个做法是所有模式都开窗口：更统一、更安全，但配对码复制出去超过 10 分钟就要重新打开弹窗。
3. 来源默认放行私有网段（推荐）局域网和常见 VPN 开箱即用；监听公网 IP 时必须用 --allow-from 写明网段，不然拒绝启动。另一个做法是一律手动填：最严，但每个人都要先搞清楚自己的网段。
4. 第一版只接受 IP 地址，不做域名和端口映射（推荐）覆盖局域网和各种 VPN 已经够用；公网服务器留给下一步的 SSH 通道。
5. 发现到的电脑用「6 位口令」确认身份（推荐）体验像蓝牙配对：选中电脑，输入它屏幕上的 6 位数字就配好，对方不用再点批准；同一网络里冒充的人拿不到口令，也没法离线猜。代价：新增一套握手（RustCrypto 的 spake2 0.4，会带进 curve25519-dalek 等几个密码学库），要专门的安全测试和评审，多花一到两天。另一个做法：发现只帮你填好名字和地址，身份照现在的办法确认，但要双向核对校验码（为了防离线碰撞，对方的码要 12 位）。不用改协议、省时间，但两边都要比对一串字符，体验一般。

风险和应对

局域网里任何设备都能连到这个端口应对：来源网段先过一遍；没配对的设备只能碰到匿名接口，而这些接口只在配对窗口里回应，并且按来源限流；其余接口都要已配对的证书（现在就是这样）。并发连接上限 64 个、TLS 握手超过 5 秒就断（已有）。
6 位校验码在更大的网络里更容易被冒充冒充要先知道发起方证书指纹的后 6 位，再离线碰撞。应对：配对窗口关着时连 hello 都不回，拿不到别人的指纹。批准时显示申请的来源地址；多条申请对得上同一个校验码就拒绝批准（已有）。要更强的保证就用完整指纹：hmesh pair approve --expect-fingerprint。
局域网 IP 变了，daemon 起不来应对：启动时明确提示原因；再跑一次 hmesh setup 换成新地址，名片同步（#15）会把新地址告诉已配对的电脑。建议在路由器上给常用电脑固定 IP。两台电脑同时换地址时要重新配对。
macOS 的「本地网络」权限（影响整个直连模式，不只是发现）苹果的规定（TN3179）：向局域网地址发起 TCP 连接、收发多播，都要「本地网络」权限。从终端或 SSH 启动的命令、launchd daemon、root 进程自动放行；我们开机自启装的是 launchd agent，不在放行之列。有开发者报告，没有 Info.plist 的裸程序连授权弹窗都不出、连接直接失败（没证实）。只是接受连入不需要权限；Tailscale、WireGuard 这类 VPN 地址也不算本地网络，所以现在的 Tailscale 模式不受影响。应对：嵌入 Info.plist；setup 提示这一步；把 EHOSTUNREACH 翻成人话。真机验证必须覆盖「开机自启的 daemon 连局域网」这条路。
新增密码学依赖和握手代码应对：锁定版本，纳入 OSV 依赖审计；握手单独评审，并针对错口令、重放、冒充广播、窗口外的请求写测试。
和旧版本不兼容旧版本只接受 Tailnet 地址，所以用直连的两台电脑都要升级。只用 Tailscale 的电脑之间不受影响。
防火墙macOS、Windows 第一次监听局域网地址时会弹窗，要允许（Windows 选「专用网络」）。setup 会提示这一步。

怎么验证

  • 两节点测试（直连模式，测试里用 127.0.0.1，允许网段设为 127.0.0.0/8）：窗口关着时配对申请被拒，打开后能配上；配对后开会话、拿回答复；不在允许网段的来源被丢弃；窗口里按来源限流。
  • 证书：证书里没有你拨的 IP 也能连上（指纹对）；指纹不对一定失败；过期证书照样失败。
  • 换地址：一边换端口或地址后，名片同步让另一边跟上。
  • hmesh setup --network direct 在临时 HOME 下走一遍；只装 MCP 在没有 Tailscale 的环境下装好、能配对出去。
  • 口令配对（两节点测试，绕开 mDNS 直接走握手）：口令对，两边互相信任；错 3 次，口令作废、之后的口令请求被拒，配对码照样能申请；只发起握手不确认的也照样扣次数；拿着别的证书冒充的一方，即使知道广播内容也配不上；窗口外的握手被拒。
  • 局域网发现：两台真机在同一个局域网里看得到对方，窗口一关就从列表里消失。mDNS 在测试机的回环接口上不一定能用，这一层以真机结果为准。
  • macOS：开机自启的 daemon 第一次连局域网时弹出授权，允许后能连；拒绝时面板给出指引。
  • 面板：配对窗口倒计时、口令、「附近的电脑」列表、「直连」标记，深浅色和窄屏截图。
  • 真机：你的 Mac 和 Windows 在同一个局域网、关掉 Tailscale，配对、开会话、批权限走一遍（需要你配合）。

  • SPAKE2：RustCrypto/PAKEs 的 spake2，稳定版 0.4.0，0.5 还是预发布。Magic Wormhole 也用 SPAKE2 做短口令配对。
