项目和旧会话：用 ACP 自带的「列出、接上」读 Agent 已有的会话，不自己解析文件

2026-11-25 的核查结论：HarnessMesh 现在只管它自己开的会话，每个 Agent 固定一个目录。Claude Code、Codex、OpenCode、Pi 的 ACP 适配器都自带 session/list（列出）和 session/load（回放并接上），HarnessMesh 的续聊代码也已经有了。所以只需要补两块：「项目」和「列出旧会话」。

4 家能用Claude Code、Codex、OpenCode、Pi 的适配器都能列出和接上旧会话（2 家本机实测）
0 行解析代码不读各家的文件格式。codeg 为此写了约 2.5 万行（只算 Claude、Codex 两个）
0.2–0.9 秒临时起一个适配器并列出会话（临时目录实测，会话很少）
旧会话不出本机只在本机面板现读，不复制；配对的电脑只能在你共享的项目里开新会话

怎么列出、接上旧会话

②里从 daemon 往后是现有代码：会话记录里存着 Agent 的会话 ID，就先试 session/load，不支持再退到 session/resume。现在回放出来的消息会被丢掉（防止重启后重复），要改成第一次接上旧会话时留下来。

各家 Agent 支持到哪

Agent（适配器版本）列出回放并接上不回放接上怎么确认的

OpenCode（1.18.33）✓✓✓本机实测：两个目录各开一个会话，不带目录列出 2 条、带目录列出 1 条；换一个进程后 load、resume 都成功。会话是空的，没测有消息时的回放

别的 ACP Agent 看它启动时声明的能力；不支持列出的，面板显示「这个 Agent 不能列出旧会话」。

分三步

步骤做什么做完你能
1. 本机：项目和旧会话项目表；从 Agent 历史勾选添加、手动添加；侧栏改成「电脑 → 项目 → 会话」；展开项目时列出旧会话；点开回放并接着聊；本机任意 Agent 在任意已添加项目里开新会话在面板里找到 Claude Code、Codex 以前的会话接着聊；同一个 Claude Code 用在多个项目里
2. 共享项目项目可以标「共享给配对的电脑」；对方能在共享的项目里开新会话；mesh_list_agents 显示可用项目，mesh_send 加 project 参数（见下一节）让别的电脑的 Agent 去你的另一个项目干活
3. 会话管理会话改名、隐藏、置顶、按标题搜索；项目改名、隐藏、排序会话多了也找得到

第 2 步：共享项目的规则

对方能做的
  • 看到你共享的项目：只给项目 ID 和名字，不给完整路径。
  • 用你开放给它的 Agent，在共享的项目里开新会话。
  • 通过 MCP：mesh_list_agents 列出每个 Agent 可用的项目，mesh_send 带 project 选一个；不带就用 Agent 登记的目录，和现在一样。
对方不能做的
  • 指定任意路径：请求里只能带项目 ID，daemon 用本机的项目表换成路径，并检查它还在共享。
  • 列出、接上你的旧会话（第 1 项定的）。
  • 绕过工具白名单和审批：都按现在的规则走，审批仍按电脑开关。
  • 取消共享后继续用：之后的新会话被拒，已开的会话从下一轮起被拒。

每个项目默认不共享，共享时对所有配对的电脑生效。兼容老版本：共享项目通过一个新接口查询，老版本电脑返回 404，就当它没有共享项目；只有对方支持时，开会话的请求里才带项目（老版本会拒绝不认识的字段）。

不做什么

  • 不自己解析各家的会话文件。
  • 不改写、不删除 Agent 自己的会话文件。面板里的「改名」「隐藏」只存在 HarnessMesh 里。
  • 不在启动时扫全部历史，不把历史整个复制进 HarnessMesh，只存你点开过的那几条会话。
  • 不支持没有 session/list 的 Agent 列出旧会话。
  • 先不做「从某一轮分叉」（session/fork 在协议里还是试验性的）。

已定的事（2026-11-25）

1. 旧会话只在本机面板看私人对话不经过配对通道，HarnessMesh 也不复制，只存你点开过的。代价是在 laptop 上看不到 studio 的旧会话。连带把工程规格书第 524 行改成「只在本机面板现读，不复制、不外传」。
2. 项目从 Agent 历史里勾选添加，也能手动添加侧栏只出现你要的项目；第一次要多点一步。
3. 配对的电脑能在你标了「共享」的项目里开会话没选推荐的「只在登记目录」。所以共享项目从原来的第 3 步提前到第 2 步，规则见上面「第 2 步：共享项目的规则」。代价：要改对外接口、配对电脑之间的协议和安全测试，比只改本机多一步工作量。
4. 侧栏按「电脑 → 项目 → 会话」同一项目里不同 Agent 的会话放在一起；配对电脑的会话没有项目信息时，仍按现在平铺。

风险和应对

终端里还开着同一个会话时，两边会同时写应对：打开旧会话前提示「如果终端里还开着它，先关掉」。HarnessMesh 没法可靠判断终端里是不是还开着。
每次列表都要起适配器，会话多了可能慢应对：只在展开项目时列，按「Agent + 目录」缓存 30 秒，有刷新按钮；不在启动时扫所有目录。0.2–0.9 秒是在临时目录、只有一两条会话时测的，真实目录没测。
「从历史添加项目」要扫全部历史，可能要翻很多页应对：后台翻页并显示进度，可以中途停；扫到的目录只用来勾选，不存会话内容。
同一个目录，各家给的路径写法不同OpenCode 实测返回 /private/tmp/…（macOS 的真实路径），而不是 /tmp/…。应对：都转成真实路径再比较。
Agent 能去的目录变多了应对：本机只能用你添加过的项目；工具白名单和权限审批照旧。
共享项目后，对方的 Agent 能在这个目录里读写文件能做什么取决于该 Agent 的工具白名单，审批按电脑开关。应对：每个项目默认不共享；面板里共享开关旁写清这一点；对方只拿到项目 ID，路径永远由本机决定；取消共享立刻生效。
共享对所有配对的电脑生效只想给其中一台时做不到。应对：先这样做；真有需要再加「按电脑共享」，协议本来就按项目 ID 检查，以后加也不用改接口。
列表里会混进 HarnessMesh 自己开的会话（包括 Agent 之间互相调用开的）应对：按 Agent 会话 ID 去重，HarnessMesh 开过的只显示一次，并保留调用关系。

怎么验证

  • 假 ACP Agent（测试用）加上列出和回放：两个目录的会话各自列对；点开旧会话后历史出现在会话里；接着发消息能续；daemon 重启后还能续。
  • 真适配器、不调模型：Claude 适配器配伪造的旧会话；OpenCode 用临时 HOME。把这次的实验脚本整理成需要手动开启的检查脚本。
  • 安全：配对电脑带旧会话 ID、路径，或带没共享的项目 ID 都被拒；取消共享后对方下一轮被拒；相对路径、不存在的目录不能添加；列出旧会话的接口只认本机主人。
  • 共享项目的双节点测试：A 共享项目 P，B 通过 MCP 用 project 在 P 里开会话并拿回结果；老版本节点（不认识项目字段）照常能互相调用。
  • 面板冒烟：侧栏、添加项目窗口、旧会话回放，深色、浅色和窄窗各截一张。
