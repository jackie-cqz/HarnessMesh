每种 agent 怎么看出「配好了没有」

agent怎么知道（不读凭据文件）能看出什么核实情况
Claude Code它的 ACP 适配器 claude-agent-acp 启动后自己推 _auth/status_update，也回答 auth/status（内部跑 claude auth status --json）。HarnessMesh 只要接住这条消息Claude 订阅（含邮箱、套餐）、API key（并说明来自 ANTHROPIC_API_KEY 还是 key helper）、网关、Bedrock / Vertex 等云账号、未登录读了适配器 0.110.1 源码 dist/auth-status.js；本机没装 Claude Code，没实测
Codex跑 codex login statusChatGPT 登录 / API key / 未登录。只读它自己存的登录，不联网验证；看不到环境变量里的 key本机 codex-cli 0.153.4 实测：Not logged in。API key 时它会打印 key 前 8 后 5 位，我们只取「API key」三个字，不显示片段
OpenCodeACP 不报（实测 auth/status、providers/list 都是 Method not found）；改跑 opencode auth list存了哪些服务商的凭据（名字 + 类型），以及环境变量里检测到哪些 key。不打印 key；没有 JSON 输出，要解析文字本机 1.18.33 实测：1 个凭据（OpenCode，api）
Pi跑 pi --list-models：只列已配好的服务商的模型。不用 pi auth，它会直接打印凭据配了几个服务商、多少个模型；看不出是订阅还是 key本机 pi 0.83.0 实测：4 个服务商、29 个模型
所有 ACP agent开新会话时 agent 报的模型选项（agent 卡片已经缓存，不调模型）它自己的默认模型和可选模型已有

「检测到已配好」不等于 key 一定能用：Codex 的状态不联网验证，订阅也可能过期。所以文案写「检测到……」，真正能不能用以第一轮对话为准（失败时已有的报错会说明）。

规则

规则怎么做
什么时候检测本机拥有者打开「模型服务」弹窗、点「重新检测」或运行 hmesh agent service <id> --check 时检测一次：同时起一次 agent 只做 ACP initialize 和 auth/status（最多 12 秒，适配器经 npx 启动可能要几秒），并跑它的状态命令（最多 10 秒）；超时显示「看不出来」。结果记到这台电脑上，卡片只带三态。都不建会话、不调模型
找不到命令登记的是 ACP 适配器（codex-acp、pi-acp），状态命令要用同一台电脑上的 codex / pi；找不到就显示「没能检测」，不影响使用
谁能看到本机弹窗：登录方式、账号邮箱、默认模型。配对电脑：只有「已配好 / 没配好 / 看不出来」
默认选哪个模式检测到已配好且没单独配过：默认「用它自己的登录」并说明；没检测到：提示怎么登录，或单独给 key。不会自动替你切换
重新配置选「单独给它一个 key」或「自定义地址」就是覆盖它自己的配置（只对这个 agent、只在 HarnessMesh 启动它时生效，不改它的配置文件）；切回「用它自己的登录」就恢复
预设照 AgentMeld 全量 28 个 + 自定义，只放地址。按 agent 类型过滤：Claude Code 只列有 Anthropic 地址的，Codex 只列有 Responses 地址的，OpenCode 列有 Chat 地址的
沿用之前定的Claude Code 选第三方模型时自动设 ANTHROPIC_MODEL 和 ANTHROPIC_DEFAULT_OPUS/SONNET/HAIKU_MODEL；key 可以只填本机环境变量名（CLI 已有 --env NAME 的同类做法）

怎么做

步骤改什么怎么判断做完
1. 检测daemon 接住 _auth/status_update（以及支持时问 auth/status），存进 agent 卡片；GET /local/agents/{id}/service 多返回「它自己的配置」详情；给配对电脑的卡片只带一个三态字段；Codex / OpenCode / Pi 的状态命令解析fixture 模拟 Claude 适配器推三种状态；本机真跑 codex login status、opencode auth list、pi --list-models；配对电脑拿不到邮箱
2. 预设和 Claude Code 模型变量28 个预设（地址 + 支持的接口），弹窗和 CLI --preset；Claude Code 自定义地址补模型变量单测覆盖按 agent 类型过滤；fixture 冒充 Claude Code 检查拿到的变量
3. 面板和 CLI弹窗顶部状态说明、「重新配置」、预设下拉；agent 卡片写清「它自己的登录（Claude 订阅）」；hmesh agent service <id> 输出也带这段面板冒烟三种状态各截一张（浅色、深色、窄窗口）

没证实的

  • Claude Code 真机上的推送时机和内容（本机没装）。
  • codex-acp、pi-acp 自己是否也报登录状态：codex-acp 包里只有启动脚本，真正的程序没下载；pi-acp 有多个分支，做法不一。
  • opencode auth list 和 codex login status 是给人看的文字，版本升级可能改格式；解析不了就显示「没能检测」。
  • 部分服务商的 Anthropic / Responses 地址（Kimi 国内站、通义国内站、OpenRouter）。
