# ADR 0003：原生 Harness 消息与 Mesh 事件分开限额

日期：2026-10-29。状态：已实施。

Pi RPC 的一条 JSONL 消息可能含累积消息快照、完整工具输入或工具输出。最初把原生帧上限设为内部事件的 64 KiB，导致正常代码生成在文件已经写出后仍被终止。提高累计 stdout 额度没有改变单帧限制，因此不能解决这个问题。

采用以下边界：

| 边界 | 限额与行为 |
|---|---|
| Pi 原生 JSONL | 最多 4 MiB，且不超过任务累计额度 |
| DSH/OpenCode 原生 JSONL | 最多 1 MiB，且不超过任务累计额度 |
| 累计 stdout | 默认 1 MiB；owner 显式提交的任务可选至多 32 MiB |
| 内部事件 payload | JSON 序列化后最多 64 KiB |
| 正文 text_delta | 脱敏后按 UTF-8 边界分段，每段至多 8 KiB 原文；最坏 JSON 转义仍在 payload 限额内 |
| 事件读取 | 最多 1000 条，同时限制整页 JSON 为 512 KiB；使用 seq 游标补读 |

这些原生上限是本项目的有界实现策略，不是上游协议的最大值声明。Pi 的上限为大工具响应和消息快照保留空间；累计预算仍可更早终止运行。保留超时、取消、进程回收、畸形 JSON 检查与资源超限失败，不能无限缓冲，也不能跳过超大消息后伪造成功。

内部事件只保留 Adapter 需要的正文和工具名称/阶段。忽略的原生快照、工具参数和结果不持久化。正文先执行原有跨消息脱敏，再拆分；诊断摘要仍按原有长度截断。存储失败经过统一进程清理路径，防止错误返回绕过进程回收。

增加不含原文的 output_summary：累计字节、额度、完整消息计数和最大完整消息字节数。正常完成仍依赖最终 assistant stop、agent_settled、退出 0 与清理证明；历史 FAILED 不改写。

命令行 `task watch` 在读取到终态后仍需按游标读完所有事件页，不能因终态而漏掉大正文的后续分段；合成终态任务通过真实 TLS/CLI 验证该行为。CLI 的测试增加现有 workspace crate `hmesh-store` 作为 dev-dependency，没有新增第三方 crate。

回归包括超过旧 64 KiB 的消息、碎片化 UTF-8、JSON 转义、长正文完整恢复、跨事件脱敏、原生/累计额度超限、事件库 payload 限额和分页补读。真实 Pi 回归使用新的隔离项目，先读取 runner 生成的引号/反斜线测试文件，再重新生成 Todo 服务端，以 output_summary 证明真实消息确实超过旧上限；测试数据不包含凭据。

真实任务 `c2c13fd7-eae0-42e4-8945-99c6784129ba` 正常 SUCCEEDED，最大原生消息 375,131 字节、累计 stdout 8,758,986 字节，新生成服务端 14 项测试通过。完整脱敏证据为 `docs/evidence/latest-pi-output-regression.json`。代码生成后的 CLI 分页收尾改动另行构建/回归；报告区分真实任务执行时的二进制与最终构建。
